## Booking transaction regressions added and verified

- Pending booking can be assigned and transitions to `ASSIGNED`.
- Driver fields and status history are committed together.
- Concurrent assignment calls serialize on the booking row; status/history remain consistent.
- Reassignment does not create duplicate status transitions.
- A database write failure rolls back the driver update.
- An illegal status transition leaves the booking and history unchanged.
- Closed/cancelled bookings reject driver assignment.
- Assignment audit events are committed with the booking mutation.

The run caught a model-mapping defect: `getBooking()` did not include the database `status` field. The mapping is included in the tested branch, and the E2E assignment/status checks pass. It also verifies that browser and server Google Maps keys are configured separately.
